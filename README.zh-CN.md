# iina-sub

**给 [IINA](https://iina.io/) 用的本地 AI 字幕。**

用完全跑在自己机器上的语音识别引擎转写本地视频。不联网，不要 API key，
不上传你的媒体。

[English](README.md)

---

## 为什么还需要一个字幕插件？

现有的 IINA 字幕插件解的都是直播的题：往前转写一点，把结果画在画面上。
这能工作，但有三件事没做到。

**iina-sub 把本地文件当成它本来的样子：一个音频已经在你硬盘上的文件。**

| | 直播类插件 | iina-sub |
|---|---|---|
| 字幕呈现 | 画在画面上的 WebView 覆盖层 | 真正的 IINA 字幕轨，IINA 里每一项字幕设置都生效 |
| 第二次打开 | 从头再转一遍 | 从缓存里秒载 |
| 拖动进度 | 要等下一块转完 | 立刻响应，因为整个文件已经转好了 |
| 整个文件夹 | 一次一个文件 | 一条命令转完当前视频旁边的所有视频 |
| 额外程序 | ffmpeg，或者一段安装脚本 | 都不需要，解码器是插件的一部分 |

## 特性

- **原生字幕轨。** 转写结果用 `sub-add` 加载，行为和下载来的字幕文件完全
  一致：字体、字号、颜色、位置、背景，在 IINA 里都按你习惯的方式工作。
- **不主动往你的文件夹里写东西。** 转写稿留在插件自己的目录里。只有一条
  命令——或一个快捷键——才会把 `<名字>.srt` 写到视频旁边。
- **字幕自己会出来。** 还没有转写稿的视频，一打开就开始转写。每转完一块
  就刷新一次字幕，你不用等一整两小时的课程处理完。
- **智能缓存。** 转写稿和一份指纹一起保存，指纹覆盖媒体文件、模型、引擎和
  语言。再打开视频字幕立刻就在。换了模型，缓存自动失效。
- **批量转写。** 一条命令转完当前视频所在文件夹里的所有视频文件。已经有
  转写稿的直接跳过。
- **引擎可插拔。** 默认用 whisper.cpp，mlx-whisper 走 Apple 神经网络，
  也可以用你自己的命令，把媒体文件转成 SRT 就行。
- **看得见的进度。** 屏幕上的 OSD 显示进度，侧边栏标签显示当前阶段、已用
  时间和最近几次转写的记录。
- **全程离线。** 音频一步都不离开你的机器。唯一会碰到网络的只有模型下载，
  而且只在你主动要求时才会发生。

## 环境要求

- macOS 13 或更高
- [IINA](https://iina.io/) 1.3 或更高
- 一个语音识别引擎和一个模型。插件会在第一次运行时把两样都取来，见下文
- Xcode 命令行工具（`xcode-select --install`），插件第一次使用时要自己编译
  音频解码器

### 识别引擎

插件需要 whisper.cpp 的 `whisper-cli` 程序。有两种获取方式，插件在第一次
运行时会让用户选：

- **让插件自己取**。约 4 MB，只下一次。插件从本仓库的发布页下载，先核对
  固定的 SHA-256 校验和，再放进自己的目录。如果 Homebrew 已经装了
  whisper.cpp，就什么都不下载。
- **用 Homebrew 装**，也就是侧边栏按钮里提到的方式：

  ```bash
  brew install whisper.cpp
  ```

还需要一个模型。第一次运行时插件会问要不要下载推荐的那个，模型目录里的每个
模型在侧边栏里都是一个按钮。也可以手动下载：

```bash
mkdir -p ~/iina-asr/models
curl -L -o ~/iina-asr/models/ggml-large-v3-q5_0.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-q5_0.bin
```

#### 该用哪个模型？

| 模型 | 大小 | 说明 |
|---|---|---|
| `ggml-large-v3-q5_0.bin` | 1031 MB | 量化模型里准确率最高的，做中文的稳妥默认 |
| `ggml-large-v3-turbo-q5_0.bin` | 547 MB | 大约快一倍，准确率略低 |
| `ggml-medium-q5_0.bin` | 514 MB | 准确率不错，速度中等 |
| `ggml-small.bin` | 465 MB | 快，但中文质量有限 |
| `ggml-base.bin` | 141 MB | 只用来试手 |

以 `.en` 结尾的模型只支持英文，会无视语言设置把什么都当成英文，对其他语言
没有意义。

在 M1 Pro 上用 `large-v3-q5_0` 实测：大约 4.7 倍实时，一小时的课程约 13 分钟
转完。

## 安装

### 从发布页安装

下载最新的 `.iinaplgz`，双击打开，IINA 会装好插件。

### 从源码安装

```bash
git clone https://github.com/wxmpro/iina-sub.git
cd iina-sub
bash scripts/package.sh
open dist/io.github.xinmin.iina-sub.iinaplgz
```

## 使用

打开一个本地视频。就这样。

之前转写过的视频会立刻加载字幕；没转写过的，插件会开始转写，第一块转完
字幕就出来了。

### 菜单

| 菜单项 | 快捷键 | 作用 |
|---|---|---|
| Generate Subtitles Now | <kbd>Alt</kbd>+<kbd>S</kbd> | 转写当前视频，或加载已有转写稿 |
| Export Subtitles Next to the Video | <kbd>Alt</kbd>+<kbd>E</kbd> | 把 `<名字>.srt` 写到视频旁边 |
| Transcribe All Videos in This Folder | | 转写当前视频旁边的所有视频 |
| Regenerate Subtitles | | 丢掉现有转写稿，重新转写 |
| Cancel Transcription | <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> | 停掉正在进行的转写 |

播放器最多显示插件菜单的前 5 项，其余收进「更多…」。插件的侧边栏标签里
显示转写进度、已转写的文件，以及每个菜单项的简短说明，还有下载模型的按钮，
以及清除已保存转写稿的按钮。

### 第一次使用

> **关于下载速度。** 插件会从 GitHub 取两样东西：它自己的语音识别程序（约
> 4 MB），以及你选定的模型（推荐的那个 547 MB）。GitHub 在国内可能很慢甚至
> 连不上。如果下载卡住了，在插件设置里填一个代理（**偏好设置 → 插件 →
> iina-sub → Proxy**，例如 `http://127.0.0.1:7890`）再试一次。除此之外插件
> 不需要网络：程序和模型就位之后，转写全程离线。

插件需要两样它不自带的东西：语音识别程序，和一个模型。打开视频时如果还没
有模型，插件会问一次要不要下载推荐的那个（547 MB）。它只下载一次，保存在
插件目录里，之后离线也能用。下载完成后，刚打开的那个视频会立刻开始转写。

识别程序插件装不了，用 Homebrew 装一次即可：

```bash
brew install whisper.cpp
```

之后插件会自己找到它。模型目录里的每个模型在插件侧边栏里都是一个按钮，
不用手输任何名字。

### 导出

转写稿默认留在插件目录里，你的视频文件夹不会被动。需要字幕文件跟视频放
一起时，按 <kbd>Alt</kbd>+<kbd>E</kbd>。文件名跟视频一致，例如 `lesson.mp4`
变成 `lesson.srt`，任何播放器都认。

下次打开这个视频时播放器会自己认出这个文件，所以插件不会再加载第二份同样
的字幕。

导出的文件沿用视频本身的权限，所以只有你能看的视频不会把它的台词留成一个
机器上谁都能读的文件。转写稿如果缺了视频里的一部分，就是不完整的，插件会
先问一句再写。

### 设置

**偏好设置 → 插件 → iina-sub**，或者插件旁边的齿轮图标。

| 设置项 | 默认值 | 含义 |
|---|---|---|
| Engine | `whisper.cpp` | 用哪个语音识别引擎 |
| whisper-cli path | `/opt/homebrew/bin/whisper-cli` | 可执行文件在哪 |
| Engine path | *(空)* | mlx-whisper 的路径，或自定义命令 |
| Model file | *(空)* | `.bin` 模型的路径 |
| Proxy | *(空)* | 下载模型时用的代理，例如 `http://127.0.0.1:7890` |
| Language | `zh` | ISO 语言代码，或 `auto` 自动识别 |
| Chunk length | `30` | 每块多少秒。块越长，模型能拿到的上下文越多 |
| Overlap | `2` | 每块之后多解一点音频，句子才不会被拦腰截断 |
| Transcribe automatically when a video is opened | 开 | 关掉后只有你主动要求才转写 |
| Load the cached subtitles when a video is opened | 开 | 打开视频时加载已有转写稿 |

## 自定义引擎

任何能把一段音频转成 SubRip 文件的本地命令都能用。命令里可以写这些占位符：

| 占位符 | 会被替换成 |
|---|---|
| `{input}` | 媒体文件的路径 |
| `{audio}` | 一段 WAV 文件的路径，里面只有当前这一块音频 |
| `{output}` | 要写出的 SRT 文件路径 |
| `{model}` | 模型文件的路径 |
| `{language}` | 语言代码 |
| `{start}` | 这一块的起点，单位秒 |
| `{duration}` | 这一块的长度，单位秒 |

比如要用某个第三方工具：

```
my-asr --input {audio} --output {output} --model {model} --lang {language}
```

命令每一块会被调用一次，写出来的时间要以这一块的起点为基准。用 `{audio}`
最省事：那个文件里就只有这一块音频。

命令通过 `/bin/sh` 执行，所以可以用管道和重定向。占位符展开成 shell 的
位置参数，因此含有引号或分号的文件名永远不会变成另一条命令。

## 工作原理

1. 文件长度直接从文件本身读，所以系统搜索索引里没有的文件，和下载文件夹
   里的文件一样能转写。
2. 当前文件的音轨被解码成 16 kHz 单声道 PCM，一次一块。离播放位置最近的
   那块先解，所以拖动进度条很便宜。
3. 解码由一个小工具完成，它基于 macOS 自带的媒体框架，首次使用时编译一次，
   编译产物放在插件目录里。不需要 ffmpeg，也不需要别的外部程序。
4. 这一块解出来的音频写成插件目录里的一个 WAV 文件，语音识别模型读这个
   文件。文件在这一块结束时立刻删掉。两个程序都不经过 shell 启动，所以
   文件名永远不可能被当成命令。
5. 每块单独转写。每块之后会多解两三秒音频，让模型能听到句尾，而不是被硬
   切断。从这段重叠里开始的提示词会被丢掉，因为下一块会正确地转出来。整块
   都是静音的块会被跳过——模型只会凭空编出一句话来。
6. 各块的提示词合并成一个 SubRip 文件，用 `sub-reload` 重新加载进播放器，
   屏幕上的字幕跟着转写进度走。
7. 转写稿旁边存一份指纹，覆盖媒体文件、模型、引擎和语言。任何一项变了，
   缓存就作废。

### 关于分块边界

只要是分块做语音识别，恰好跨在边界上的词都可能被重复一遍。这是正常现象，
也没有危害：时间轴不会重叠，文件也不会少内容。在设置里把块调长一些，边界
的数量就少了。

## 安全性

插件只运行你自己装好的东西，并且把你的文件名当作不可信输入来对待。

- 模型从你指定的路径读取。插件不会在你没要求的时候下载任何东西，它只认识
  模型仓库这一个地址。下载下来的模型会对照上游公布的体积和 SHA-256 校验和，
  对不上就直接丢弃。目录里的模型在用之前也会查一遍同样的校验和，因为引擎
  是把它当程序加载的。
- 读取视频音频的辅助程序由插件自己编译，只有在它仍带着编译时记下的校验和
  时才会使用；被改过的文件会重新编译一份。
- 文件名不会以文本的形式进入侧边栏，它以自己的字节过去，所以名字里就算
  藏着 JavaScript 的记号，也没法在那页上被执行。
- 下载时不读你自己的任何配置。属于你的 `curl` 配置会被忽略，所以你手上的
  文件没法把下载指到别处去。
- 你的文件名永远不会进入 shell 命令。内置引擎把参数原样交出去，自定义引擎
  拿到的参数是彼此独立的值，而不是让 shell 去解析的一段文本。
- 转写稿的文件名来自媒体路径的哈希，所以文件名无法影响文件写到哪里。
- 导出只写进视频所在的文件夹，绝不写到外面去。那里本来有的文件是被替换，
  不是被顺着链接写穿，所以放一个链接没有用处。视频所在的文件夹里也不会
  多出别的文件。
- 插件只申请四个权限：`file-system` 用来读视频和写转写稿，`show-osd` 用来
  显示进度，`show-alert` 用来弹对话框，`network-request` 用来下载模型。
  音频本身一步都不离开你的机器。

## 开发

```bash
bash scripts/package.sh
```

打包产物就是 IINA 安装的 `.iinaplgz` 文件。它其实是个普通的 ZIP 包，只是
名字带了个后缀；里面的文件是平铺的，没有多套一层目录。

读音频的那个小工具有两份：`tools/vina.swift` 是给人看的，`decoder.js` 里
嵌着的是插件随身携带的那份。两份必须一模一样，打包时会检查这一点。

代码是怎么组织的、改完之后该验证哪些地方，见 [CONTRIBUTING.md](CONTRIBUTING.md)。
